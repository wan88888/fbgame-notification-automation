# 测试目录说明

这些文件是开发和维护时运行的自动检查，不是运营数据，也不是平台运行时必须加载的业务代码。正常启动 API、打开运营页面、执行定时任务不会运行它们；前端构建不包含这个目录。请保留在源码仓库中，部署产物可排除测试文件。

- `sop-service.test.ts`：计划状态、重复发布保护、删除与恢复、执行前检查、通知重试及调度。
- `sop-analytics.test.ts`：发送量、CTR、召回率、缺失数据和可比较的统计窗口。
- `automation-outcomes.test.ts` / `steps-state.test.ts`：失败不能误报成功，开启状态需回读，不能误删其他计划。
- 其他文件覆盖 CSV 格式、排期、日期转换、通知内容和原有执行器行为。兼容执行器仍使用的功能应保留相应测试。

运行：在仓库根目录执行 `npm test`；完整检查使用 `npm run ops:check`。SOP 服务测试使用临时目录和模拟接口，不写入运营计划、不调用真实 Facebook 或飞书。

保留能验证业务边界和曾经修复过的问题的测试；功能正式移除时同步清理其测试。重复、失效或只复述实现的用例可以合并或删除，不以测试数量作为功能完成依据。自动测试不能替代真实账号上的业务验收。
